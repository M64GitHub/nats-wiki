# nats-server v2.14.6 — every `-ERR` a client can be sent, the two slow-consumer branches, and the credential-expiry timer

Extracted line ranges, verbatim, with their real line numbers at the tag
(`https://github.com/nats-io/nats-server/blob/v2.14.6/server/<file>#L<line>`). Read for step 4 of
`inbox/plan-the-client-side-2026-09-03.md` — the server side of
`wiki/gotchas/slow-consumer-in-the-client.md` and
`wiki/gotchas/connection-closed-after-auth-error.md`, and the authority against which
`raw/nats-docs/reference/system/errors.md` and `raw/nats-docs/reference/protocols/client.md` were
swept. The behaviour is run in `raw/nats-server-src/client-faults-observed-v2.14.6.md`.

What the ranges settle:

- an `-ERR` reaches a client only through `sendErr` / `sendErrAndDebug` / `sendErrAndErr`, and only
  for `CLIENT`-kind connections — so the complete list of strings a client can be sent is the list
  of arguments to those three functions, given below;
- the four credential paths send four **different** strings — `Authentication Timeout`,
  `User Authentication Expired`, `Account Authentication Expired`, `User Authentication Revoked` —
  and every other rejection collapses into the single `Authorization Violation`, sent *regardless*
  of the internal auth error (`client.go:2529–2530`);
- the server's slow consumer has **two branches**, `write_deadline` and `max_pending`, with
  different log lines and different `ClosedState`s, and **neither sends an `-ERR`**:
  `markConnAsClosed` sets `skipFlushOnClose` for both, so the client sees only EOF;
- `ClosedState` has 37 values, and their `.String()` forms are what `/connz` reports as `reason`;
- an already-expired user JWT that slips past `jwt/v2`'s one-second-resolution check is *accepted*
  and then expired **immediately**, because `setExpiration` leaves `expiresAt` at 0 and
  `setExpirationTimerUnlocked` calls `time.AfterFunc(0, c.authExpired)`;
- an **account** JWT's expiry runs on the account, not the connection: `expiredTimeout` walks every
  client of the account and calls `accountAuthExpired`;
- `handshake_first` accepts `true` / `false` / `"auto"` / `"auto_fallback"` / any duration, and the
  50 ms in `DEFAULT_TLS_HANDSHAKE_FIRST_FALLBACK_DELAY` is the value `"auto"` picks; the startup
  warning is logged only when there is **no** fallback.
