# gh#7362 — How are NATS routez/connz rtt measured?

Category: Q&A · opened 2025-09-28 by @debbyglance (author_association: NONE) · **answer chosen** ·
state: closed · 7 comments

## Original post

We are using nats core and sometimes observe high rtt times in /routez

Exactly how is the "rtt" value calculated?

Is it based on some sort of ping/pong round trip time?
Can it be affected by client connections?

What about "rtt" in /connz ?  How is that calculated?

## Comment 1 — @derekcollison (MEMBER), 2025-09-28 — the chosen answer

Yes it is via periodic PING/PONG response times.

## Comment 2 — @debbyglance, 2025-09-29

Thank you.  And if routez rtt is high, is that always (or nearly always) an indication of a problem in the cluster, vs a problem caused by consumers?  In our case we have no slow consumer errors and rarely see pending messages in nats-top

## Comment 3 — @derekcollison (MEMBER), 2025-09-29

We track these over time. Anomalies should be few since modern version so fthe server do very little processing inline with processing the network packets. But if you see an anomaly and it is not an underlying hardware issue check the logs for the server, many times it will point to the issue.

## Comment 4 — @debbyglance, 2025-09-29

And what is the significance of the rtt value in the /connz output?  How is it measured, and how often is it updated?

## Comment 5 — @derekcollison (MEMBER), 2025-09-29

It is measured between the connected server and the client. It is done on initial setup of a connection and periodically as the connection ages.

## Notes on provenance

The chosen answer ("periodic PING/PONG response times") is correct but does not give the period. The
thread's **last technical question** — comment 6, the observation that `/connz` `rtt` is set at
connect and then does not change over minutes — receives no technical reply; the final maintainer
comment is a referral to commercial support. The reporter's observation is **accurate and explained by
the source**: `DEFAULT_RTT_MEASUREMENT_INTERVAL` is `time.Hour`, and a client's first `rtt` is the
connection setup time rather than a ping round trip. See
`raw/nats-server-src/monitoring-observed-v2.14.6.md`.
