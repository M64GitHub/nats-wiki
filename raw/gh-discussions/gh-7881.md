## Comment — @mg1986jp (2026-05-28)

Cross-domain JetStream sourcing in a supercluster with leafnodes is a bit tricky. The leafnodes need to be able to reach the JetStream streams in the supercluster, and the way to do this is through account-level imports/exports of the JetStream API subjects.

In your supercluster account config, you need to export the `$JS.API.>` subjects so the leafnodes can access them. On the leafnode side, import those subjects into the same account. This lets the leafnode's JetStream clients talk to the supercluster's JetStream.

For the sourcing itself, when you create a stream on the leafnode that sources from the supercluster, the stream's `sources` config needs to reference the stream name as it exists in the supercluster. If the accounts are different, you'll also need to set the `external` field in the source config with the `api` prefix pointing to the imported JetStream API subject.

Make sure the leafnode's credentials have permission to subscribe to the subjects being sourced. TLS cert-based auth should work fine here as long as the cert maps to the right user/account on both sides.
