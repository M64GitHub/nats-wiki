### Reply — @neilalexander (2024-11-21)

Yes, it's definitely not OK for filestore if directories/files disappear from under the server. We do in-memory caching of filestore blocks to help speed up accesses, and if you are worried about how much space on disk you'll take up, you should use stream limits.

### Reply — @neilalexander (2024-11-21)

Many Linux distributions have tools, such as `tmpwatch`, `tmpreaper` and `tmpfiles.d`, enabled by default to automatically delete files from tmpfs after they reach a certain age. You should never rely on RAM disks being anything other than temporary.

This is not JetStream behaviour and the post you linked from 2016 is pre-JetStream (it is for the deprecated NATS Streaming).

### Reply — @neilalexander (2024-11-21)

I should add, we do have a memory store option for streams if you _really_ want to keep the data in memory instead of on disk, with the obvious caveat that the data goes away when the process restarts, but pointing the file store to tmpfs is not a supported/endorsed configuration.
